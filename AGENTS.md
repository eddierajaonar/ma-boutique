## Project overview

WooCommerce store for a restaurant (pizzas, side dishes), with a **classic PHP WordPress theme written from scratch** (no block theme, no `theme.json`, no page builder).

- Docker Compose (`docker-compose.yml`): `db` (MariaDB 10.11), `wordpress` (`wordpress:php8.3-apache`, WordPress 7.x), `phpmyadmin`.
- Site: http://localhost:8080/ — phpMyAdmin: http://127.0.0.1:8082/
- Only `./wp-content` is mounted into the container (`/var/www/html/wp-content`). WordPress core lives inside the container.
- Containers: `ma-boutique-wordpress-1`, `ma-boutique-db-1`, `ma-boutique-phpmyadmin-1`. DB credentials come from `.env` (never commit it; `.env.example` is the template).
- Active plugin: WooCommerce only. Permalinks: `/%postname%/`. Shop page: `/shop/`.
- Product data to import: `pizzas_woocommerce.csv`, `accompaniements_woocommerce.csv`.

## Theme: `wp-content/themes/ma-boutique/`

```
style.css            theme header (required) + small custom CSS, loaded AFTER Tailwind
functions.php        theme supports + ma_boutique_version() + ma_boutique_scripts()
header.php           doctype, <head>, wp_head(), <body>, wp_body_open(), <header>, opens <main>
footer.php           closes </main>, <footer>, wp_footer()
index.php            fallback template
front-page.php       home page (<section class="hero">)
src/input.css        Tailwind v4 source
assets/css/main.css  GENERATED by Tailwind (gitignored, never edit)
assets/js/vendor/    GENERATED: GSAP copied from node_modules (gitignored, never edit)
assets/js/animations-home.js   loaded only if is_front_page()
assets/js/animations-shop.js   loaded only if is_shop() || is_product_taxonomy()
scripts/copy-vendor.js         copies node_modules/gsap/dist/* -> assets/js/vendor/
package.json         scripts: build, watch, vendor, postinstall (= vendor + build)
```

The original Underscores starter was moved to `_backup_underscores/` (gitignored, reference only).

### Front-end tooling (run on the host, not in Docker, from the theme folder)

- `npm ci` — install exact versions; `postinstall` runs `vendor` then `build`.
- `npm run watch` — Tailwind watch. `npm run build` — minified Tailwind.
- `npm run vendor` — re-copy GSAP files.
- Tailwind v4 via `@tailwindcss/cli`; `src/input.css` uses `@import "tailwindcss" source(none);` + `@source "../**/*.php";` + `@source not "../node_modules";`. Classes must appear as complete strings in theme PHP files (no string concatenation). HTML generated by WooCommerce/WordPress is not scanned: target their classes with `@apply` in `src/input.css`, or override the template in the theme.
- GSAP 3.x is loaded as plain scripts (no bundler): `gsap` and `gsap-scrolltrigger` are **registered** (`wp_register_script`) and only loaded as dependencies of page-specific animation scripts (`wp_enqueue_script`, `in_footer`). The global `gsap` / `ScrollTrigger` objects are used.
- To add an animated page: create `assets/js/animations-<page>.js` and add an `if ( conditional_tag() )` enqueue block in `ma_boutique_scripts()`.
- `npm audit` reports `braces` (via `@parcel/watcher`, dev-only). **Do not run `npm audit fix --force`** (it downgrades `@tailwindcss/cli`).

## Conventions

- WordPress PHP coding style: tabs for indentation, spaces inside parentheses (`foo( $bar )`), as in existing code.
- Prefix all theme functions and handles with `ma_boutique_` / `ma-boutique-`.
- Escape output (`esc_url()`, `esc_html()`, `esc_attr()`).
- Load CSS/JS only via `wp_enqueue_style` / `wp_enqueue_script` in `ma_boutique_scripts()`, never with hardcoded `<link>` / `<script>` in templates. Version theme assets with `ma_boutique_version( 'relative/path' )` (filemtime, safe if the file is missing).
- Guard WooCommerce functions with `function_exists()` (e.g. `function_exists( 'is_shop' )`) so the theme doesn't fatal if WooCommerce is disabled.
- Code comments in French, short, matching the existing style.
- Every template starts with `get_header()` and ends with `get_footer()`.

## WooCommerce rules

- **Never edit files in `wp-content/plugins/`.** Customize via hooks in `functions.php` (preferred) or by copying the smallest possible template from `wp-content/plugins/woocommerce/templates/` to `wp-content/themes/ma-boutique/woocommerce/` (same relative path).
- The theme declares `add_theme_support( 'woocommerce' )`. The default WooCommerce CSS (`woocommerce-layout`, `woocommerce-smallscreen`, `woocommerce-general`) is currently **enabled**. It can be disabled via the `woocommerce_enqueue_styles` filter.

## Known pitfalls (already hit)

- **WooCommerce "Coming soon" mode** (`woocommerce_coming_soon = yes`): logged-out requests (including `curl`) get the coming-soon page instead of the theme. Check while logged in, or set the site live (WooCommerce → Settings → Site visibility). Keep this in mind when testing with `curl`.
- `front-page.php` only applies to `/`. `/shop/` uses WooCommerce's `archive-product.php`.
- Without `get_header()`, `wp_head()` doesn't run, so no CSS: the admin bar renders as a raw list.
- CSS sizing must target the `<img>` (e.g. `.custom-logo`), not its wrapper; `width`/`height` HTML attributes on images are normal and overridden by CSS.
- Tailwind `--watch` exits immediately when stdin is closed (non-TTY / background): use `--watch=always` for background tests, and never write log files inside the theme while watching (rebuild loop).
- File permissions: the container writes as `www-data`; the host user edits files. See `Note_importante.txt` (`chmod -R 777 wp-content`, local only).

## Useful verification commands

```bash
# PHP syntax check inside the container
docker exec ma-boutique-wordpress-1 php -l /var/www/html/wp-content/themes/ma-boutique/functions.php

# Read WordPress options from the DB
docker exec ma-boutique-db-1 sh -c 'mariadb -u"$MARIADB_USER" -p"$MARIADB_PASSWORD" "$MARIADB_DATABASE" -e "SELECT option_name, option_value FROM wp_options WHERE option_name IN (\"template\",\"show_on_front\",\"woocommerce_coming_soon\");"'

# Which CSS/JS a page loads
curl -s localhost:8080/shop/ | grep -o "<link[^>]*stylesheet[^>]*>\|<script[^>]*src=[^>]*>"
```
